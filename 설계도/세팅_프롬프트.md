# 1. 프로젝트 개요와 폴더 구조

## 개요

국유재산 업무 전반(사용허가·기부채납·변상금·용도폐지·회계 처리·대부·처분·취득)에 대한 법령 검토 요청을 받아, 사안을 분류하고 근거 조문·유사 선례·확인 필요 사항을 정리한 **검토서 초안**을 만드는 에이전트입니다.

참고자료 보유 수준에 따라 응답 깊이를 달리하고, 근거가 확보되지 않은 영역은 반드시 그 사실을 밝힙니다.

# 2. CLAUDE.md

프로젝트 루트에 아래 내용으로 `CLAUDE.md`를 만드세요.

````markdown
# 국유재산 법령해석 검토 에이전트

국유재산 업무의 법령 검토 요청을 받아 검토서 초안과 근거자료를 만든다.

## 절대 규칙

1. **조문 호 번호는 반드시 법령 md에서 확인한다.** 사례 문서의 호 번호를 그대로 쓰지 않는다.
2. **`참고자료/사례요약.md`의 "근거 미기재" 항목은 선례로 인용하지 않는다.**
3. **참고자료에 없는 근거는 인용하지 않고 "확인 필요"에 기재한다.**
4. **교내 기준은 법령 근거로 인용하지 않는다.**

## 업무 영역과 응답 수준

| 영역 | 확보된 법령 근거 | 사례 | 응답 수준 |
|---|---|---|---|
| 사용허가 | 법령 4종 발췌 + `법령제외규칙.md` | 3건 | **정식 검토** |
| 변상금 | 법 제72조·제73조·제73조의3·제73조의4·제74조·제75조·제82조 / 영 제71조·제72조·제73조 / 규칙 제49조·제49조의2 | 1건 | **정식 검토** (판결문 원문 미확보 — 판례 인용 시 「확인 필요」로 처리) |
| 기부채납·무상사용허가 | 법 제2조제2호·제34조제1항제1호 / 영 제32조·제33조 — 법 제13조 미발췌 | 1건 | **검토 가능** (법 제13조 미확보를 결과물에 명시) |
| 용도폐지 | 법 제40조·제40조의2 / 영 제37조·제37조의2 / 규칙 제14조제4항·제22조 | 없음 | **검토 가능** (선례 없음을 결과물에 명시) |
| 회계 처리 | 국립대학회계법 제11조·제13조·제19조·제23조·제25조·제26조 | 1건 | **검토 가능** (교육부령·예산집행 기본지침 미확보) |
| 대부 | 법 제47조제1항(참조 조문)뿐 | 없음 | **범위 밖** |
| 처분 (매각·교환·양여) | 법 제27조 / 영 제19조뿐 | 없음 | **범위 밖** |
| 취득 (공유지분 매입 등) | 없음 | 2건 | **범위 밖** |

※ 참고자료를 추가하면 해당 영역의 수준이 올라간다. 이 표와 `설계도/기획서.md` 부록 1을 함께 갱신한다.

## 응답 수준 판정 기준

| 보유 상태 | 응답 수준 |
|---|---|
| 법령 발췌 + 사례 **모두 있음** | 정식 검토서 |
| **일부만 있음** | 검토하되 미확보 근거를 명시 |
| **없음** | 범위 밖임을 밝히고 일반 안내만 |

## 수준별로 결과물에 반드시 들어가야 하는 것

| 응답 수준 | 결과물 처리 |
|---|---|
| 정식 검토 | 조문·선례를 모두 인용한 검토서 |
| 검토 가능 | 검토서 + **미확보 근거를 「확인 필요 사항」에 특정해서 기재** (예: "법 제13조 원문 미확보") |
| 범위 밖 | 검토서를 만들지 않고 **범위 밖임을 밝히고 일반 안내만**. 조문을 인용하지 않는다 |

## 참고자료

| `참고자료/법령_국유재산법시행령_사용허가.md` | 요율·금액·요건·절차 |
| `참고자료/법령_국유재산법시행규칙_사용허가.md` | 서식·면적 산정·고지 절차 |
| `참고자료/법령_국립대학회계법.md` | 재산 귀속·사용료 세입 |
| `참고자료/사례요약.md` | 유사 선례 |
| `참고자료/법령제외규칙.md` | 교내 기준·판례·실무 확인사항 |
| `참고자료/양식_사용허가_검토보고서.hwpx` | 결과물 서식 |

조문 대조 색인은 `설계도/기획서.md`의 **부록 1**(영역·쟁점별 근거 조문)과 **부록 2**(시행령 제27조 각 호)를 쓴다.

## 다 됐다고 볼 기준

- 업무 영역과 쟁점이 분류되어 있고, 응답 수준(정식 검토 / 일부 근거 미확보 / 범위 밖)이 명시되어 있다
- 검토 결론이 「검토 결론의 형태」 중 하나로 확정되어 있다
- 인용한 조문·호 번호를 법령 md에서 확인해 `[파일명 · 조번호]`로 표기했다
- 요건과 본 건 사실관계의 대응이 조문별로 적혀 있다
- 확인 필요 사항이 별도로 명시되어 있다
- 참고자료에 근거가 없는 부분은 그 사실이 결과물에 드러나 있다
- 추측으로 채운 문장이 없다
````

# 3. 서브에이전트

`.claude/agents/` 아래에 두 개를 만드세요. **3단계와 4단계는 병렬로 실행합니다** — 한 메시지에서 두 에이전트를 동시에 띄우세요.

## 3-1. `.claude/agents/법령검색담당.md`

````markdown
---
name: 법령검색담당
description: 사안의 업무 영역·쟁점에 해당하는 근거 조문을 참고자료 법령 md에서 찾아 요건을 사실관계와 대조한다. 워크플로우 3단계에서 사례검색담당과 병렬로 실행한다.
tools: Read, Grep, Glob
---

당신은 국유재산 법령 조문 대조를 담당한다.

## 하는 일

`설계도/기획서.md`의 **부록 1**(영역·쟁점별 근거 조문 대조 대상)에서 해당 영역·쟁점 행을 찾고, 그 조문을 참고자료 법령 md에서 읽어 **요건을 본 건 사실관계와 하나씩 대조**한다.

## 대조 규칙

- 요건이 각 호로 열거된 사안은 **제1호부터 순서대로** 대조하고, 포괄 사유는 마지막에 본다.
- 계약방법 사안은 **부록 2**를 쓴다. 대조 순서는 다음과 같다.
  1. 영 제27조**제3항** 제1호~제8호 (구체적 요건)
  2. 해당 호가 없을 때만 영 제27조**제3항 제9호** (포괄 사유)
  3. 제3항에 해당하지 않으면 영 제27조**제2항** (제한경쟁·지명경쟁)
  4. 제2항에도 해당하지 않으면 **일반경쟁**
- 제3항 제9호를 적용하는 경우 "왜 경쟁입찰에 부치기 곤란한지"를 본 건 사실관계로 적는다.
- 법 제36조·영 제35조는 **현행본과 2026. 8. 20. 시행본 2종**이 있다. 처리 시점을 판단해 어느 버전인지 밝힌다.

## 절대 규칙

1. **호 번호는 반드시 법령 md 본문에서 확인한다.** 부록 1·2는 색인이고, 사례 문서의 호 번호는 그대로 쓰지 않는다.
2. 참고자료에 없는 근거는 인용하지 않고 **"확인 필요"** 로 넘긴다.
3. 교내 기준을 법령 근거로 인용하지 않는다.

## 반환 형식

| 조문 | 요지 | 본 건 사실관계와의 대응 | 해당 여부 | 출처 |
|---|---|---|---|---|
| 영 제27조제3항제○호 | (조문 요지) | (사실관계 대조) | 해당 / 미해당 | `[파일명 · 조번호]` |

- 마지막에 **미확보 근거 목록**을 따로 적는다 (참고자료에 없어 확인하지 못한 조문).
- 조문을 인용할 때는 `[파일명 · 조번호]`를 병기한다.
````

## 3-2. `.claude/agents/사례검색담당.md`

````markdown
---
name: 사례검색담당
description: 참고자료/사례요약.md에서 같은 영역·같은 근거 조문을 적용한 교내 선례를 찾는다. 워크플로우 4단계에서 법령검색담당과 병렬로 실행한다.
tools: Read, Grep, Glob
---

당신은 교내 선례 조회를 담당한다.

## 하는 일

`참고자료/사례요약.md`에서 **같은 업무 영역·같은 근거 조문을 적용한 건**을 찾는다.

## 조회 규칙

- 영역이 같아도 **적용 조문이 다르면 선례가 아니다.** 조문 단위로 맞춘다.
- **`사례요약.md`에서 "근거 미기재"로 표시된 항목은 선례로 인용하지 않는다.** 단 그 표시가 사안의 어느 부분에 걸린 것인지 확인한다 — 사례 1의 「근거 미기재」는 사용료율·허가기간에만 걸리고, 수의계약 판단 자체는 2020년 법률자문이 근거로 기재되어 있다.
- 사례 문서에 적힌 조문 호 번호를 그대로 쓰지 않는다. 호 번호는 법령검색담당의 결과를 따른다.
- 업체명·개인 성명은 `사례요약.md`의 익명 부호(`A업체`, `A개인` 등)를 그대로 쓴다. 익명 부호는 사례별로 부여된 것이므로 사례 간에 이어지지 않는다.

## 선례가 없을 때

**"교내 선례 없음"을 반환한다.** 참고자료에 없는 선례를 만들어내지 않는다. 특히 다음은 선례가 없다.

- 영 제27조제3항 **제1호~제8호** 적용 건
- 영 제27조**제2항** 적용 건
- **용도폐지** 영역

## 반환 형식

| 사례 | 사안 유형 | 적용 조문 | 결론 | 근거 기재 | 원본 파일명 |
|---|---|---|---|---|---|

- 선례가 없으면 표 대신 **"교내 선례 없음"** 과 그 근거(어느 파일에서 무엇을 찾았는지)를 적는다.
````

# 4. 워크플로우 (6단계)

메인 세션이 아래 순서로 진행합니다.

| 단계 | 하는 일 | 수행 |
|---|---|---|
| 1 | **사안 분류** — 문의 내용에서 **업무 영역**과 **쟁점**, 그리고 대상 재산·신청인·용도·기간·면적·**특수관계(협약 등)** 를 추출 | AI → **사람 확인 ★** |
| 2 | **참고자료 보유 확인** — 해당 영역의 법령 발췌·사례가 참고자료에 있는지 확인하고 **응답 수준을 결정** | AI |
| 3 | **요건 대조** — `법령검색담당` 실행 | AI |
| 4 | **유사 선례 검색** — `사례검색담당` 실행 | AI |
| 5 | **리스크·확인사항 도출** — `참고자료/법령제외규칙.md` 대조, 판단에 필요한데 확보되지 않은 사실을 식별 | AI |
| 6 | **결과물 생성** — 검토서(hwpx) + 근거자료(md) | AI → **사람 최종 확인 ★** |

## 사람 확인 지점 2곳

**★ 1단계 직후 — 사안 정보 확정**
추출한 항목을 보여 주고 **누락 항목을 질문**한다. 사용자가 확정하기 전에 2단계로 넘어가지 않는다.

- 사용자가 **"모름" 또는 "그대로 진행"** 이라고 답하면 해당 항목을 **「확인 필요 사항」으로 넘기고** 2단계로 진행한다.
- **질문은 한 번만 한다.** 같은 항목을 반복해서 묻지 않는다.

**★ 6단계 직후 — 최종 확인**
결과물 2종을 만든 뒤 사용자 확인을 받는다. 검토서는 1차 초안이며 최종 판단은 담당자가 한다.

## 3단계·4단계는 병렬

두 서브에이전트를 **한 메시지에서 동시에** 실행한다. 4단계는 3단계 결과를 기다리지 않는다. 단 **호 번호는 법령검색담당의 결과를 정본으로 삼는다**(절대 규칙 1).

## 2단계가 「범위 밖」으로 판정한 경우

3~6단계를 진행하지 않는다. **범위 밖임을 밝히고 일반 안내만** 하고, 조문을 인용하지 않는다.

# 5. 결과물 2종

**파일명 규칙**

- 검토서: `결과물/YYYYMMDD_사안명_검토서(1차초안).hwpx`
- 근거자료: `결과물/YYYYMMDD_사안명_근거자료.md`
- 두 파일은 같은 `YYYYMMDD_사안명` 을 쓴다.

## ① 국유재산 법령해석 검토서

- **형식**: hwpx, **위치**: `결과물/`
- **서식**: `참고자료/양식_사용허가_검토보고서.hwpx`의 구조를 따른다. **서식·글머리만 따르고 본문 내용은 쓰지 않는다.**

**구성**

1. 사안 분류 (업무 영역 · 쟁점)
2. 응답 수준 (정식 검토 / 일부 근거 미확보 / 범위 밖)
3. 검토 결론
4. 근거 조문 및 요건 대응
5. 유사 선례
6. 후속 절차
7. 확인 필요 사항

**양식 골조**

| 순서 | 절 |
|---|---|
| 제목 | 「○○ 국유재산 ○○ 검토」 (영역명 반영) |
| 머리 | `<'YY. M. D.(요일), 부서>` |
| 1 | `□ 검토배경` (사안 분류·응답 수준 포함) |
| 2 | `□ 검토 결과` |
| 3 | `□ 참고사항` |
| 4 | `□ 유사 선례` |
| 5 | `《관련 법령》` 인용 박스 |

`□` 대절 → `◦` 중절 → `-` 소절 글머리를 쓰고, 인용 자료는 `《 》` 박스로 감싼다.

**작성 규칙**

- 「참고사항」에는 본 건 결론에 직접 관계되는 사항만 적는다.
  결론과 무관한 용어 설명·일반 상식은 넣지 않는다.

**생성 방법**

- `참고자료/양식_사용허가_검토보고서.hwpx` 를 복사한 뒤 `Contents/section0.xml` 의 텍스트만 교체한다.
- `header.xml` 등 서식 관련 XML은 수정하지 않는다.
- 문단이 양식보다 더 필요하면 기존 문단 구조를 복제해서 쓴다.
- 생성 후 zip 무결성을 확인한다.
- hwpx 생성에 실패하면 같은 내용을 md로 저장하고 **실패 사실을 사용자에게 알린다.** 임의 형식으로 대체하지 않는다.

**고정 문구 2개 — 반드시 넣는다**

| 위치 | 문구 |
|---|---|
| 제목 | **"1차 검토 초안"** |
| 하단 | **"최종 판단은 담당자가 수행"** |

**검토 결론의 형태** — 사안 유형에 따라 다르다. 어느 쪽이든 **하나로 확정**해서 적는다.

| 사안 유형 | 결론 형태 |
|---|---|
| 계약방법 판단 | 수의계약 / 제한·지명경쟁 / 일반경쟁 / 추가확인 |
| 요건 충족 여부 판단 (감면·전대 승인·기간 연장 등) | 가능 / 불가 / 추가확인 |
| 금액 산정 | 산출액 + 적용 요율·근거 조문 |
| 절차 안내 | 단계별 절차 + 필요 서식 |
| 범위 밖 | 범위 밖 고지 + 일반 안내 |

## ② 검토 근거자료

- **형식**: md, **위치**: `결과물/`
- **구성**
  1. 적용 법령표 (조문 · 요지 · 검토서 반영 위치 · 출처 파일)
  2. 유사 선례표
  3. 확인 필요 사항
  4. 근거 없어 판단 보류한 항목

# 6. 실행 예시

아래는 구축 후 동작을 확인하는 예시다. **예시 입력의 사안 내용은 가정이다.**

## 예시 입력

> 교내 행사 목적으로 4개월간 건물 일부를 쓰겠다는 사용허가 요청이 들어왔습니다. 수의계약이 가능한가요?

## 1단계 — 사안 분류 → 사람 확인 ★

```
업무 영역 : 사용허가
쟁점      : 계약방법
대상 재산 : (미확인)
신청인    : (미확인)
용도      : 교내 행사
기간      : 4개월
면적      : (미확인)
특수관계  : (미확인)
```

→ 미확인 5개 항목을 질문한다. 사용자가 확정할 때까지 2단계로 넘어가지 않는다.

## 2단계 — 응답 수준 결정

사용허가 영역 → 법령 4종 + 사례 3건 보유 → **정식 검토**

## 3단계·4단계 — 병렬 실행

**법령검색담당** — 부록 1의 `사용허가 / 계약방법` 행 → 법 제31조 → 영 제27조제3항. 부록 2 순서로 제1호부터 대조.

| 조문 | 대조 | 해당 여부 |
|---|---|---|
| 영 제27조제3항제1호 | 주거용 아님 | 미해당 |
| … 제2호~제6호 | 각 요건 미해당 | 미해당 |
| 영 제27조제3항제7호 | 사용목적·계절적 요인 등을 고려한 **6개월 미만** 사용허가 — 본 건 4개월 | **해당** |

→ 제7호에서 해당이 확인되므로 제8호·제9호와 제2항은 보지 않는다. 조문 인용은 `[법령_국유재산법시행령_사용허가.md · 제27조제3항제7호]`로 표기.

**사례검색담당** — `사례요약.md` 조회. 사용허가 사례 3건은 사례 1·3이 제9호, 사례 2가 입찰/수의 판별 불가.

→ **"교내 선례 없음"** 반환 (제3항 제1호~제8호 적용 선례는 참고자료에 없음).

## 5단계 — 리스크·확인사항

`법령제외규칙.md` 대조 → 해당 항목 확인. 1단계에서 미확인으로 남은 사실(대상 재산·신청인·면적 등)을 확인 필요 사항으로 정리.

## 6단계 — 결과물 생성 → 사람 최종 확인 ★

**검토서** (`결과물/`, hwpx)

- 제목에 **"1차 검토 초안"**
- `□ 검토배경` — 사안 분류(사용허가 / 계약방법), 응답 수준(정식 검토)
- `□ 검토 결과` — 결론 **"수의계약"**, 근거 영 제27조제3항제7호, 요건 대응(6개월 미만 ↔ 4개월)
- `□ 유사 선례` — **"교내 선례 없음"**
- `《관련 법령》` — 법 제31조, 영 제27조제3항 인용
- 하단에 **"최종 판단은 담당자가 수행"**

**근거자료** (`결과물/`, md)

- 적용 법령표 — 조문 · 요지 · 검토서 반영 위치 · 출처 파일
- 유사 선례표 — "교내 선례 없음"
- 확인 필요 사항 — 1단계 미확인 항목
- 근거 없어 판단 보류한 항목

→ 사용자 확인을 받는다.
